## Scope (one seam)

Only the `JobEvent` DTO and `jobs_registry::emit_result` change — one DTO seam per `.plan/README.md:44`. `JobEvent` is a flat DTO (`api-types:2453-2501`), not an enum variant; the four new keys sit beside `artifact_id`/`sha256`/`size_bytes`. `kind` is already the modality label (`api-types:2460-2462`) and must not be reused as an artifact kind. No historical backfill: only frames emitted after this change carry the keys; live registry entries and stored artifacts are untouched.

- `crates/api-types/src/lib.rs:2453-2501`: add `artifact_name: Option<String>`, `artifact_kind: Option<String>`, `artifact_index: Option<u32>`, `artifact_primary: Option<bool>` with `#[serde(skip_serializing_if = "Option::is_none")]`.

- Primary policy: images mark generation index 0; Blender marks the `model` artifact when one exists. Every other artifact frame leaves `artifact_primary` unset, so zero primaries is valid. Inline delivery emits no frame at all (`images_generate.rs:600-603`). The NSFW re-emit (`jobs_registry.rs:355-368`) is an extra artifact-less frame: excluded from the primary count, unchanged by this ticket. Artifact-less annotation frames are outside this contract.
- Regenerate TS bindings/OpenAPI through `bun run codegen:check`; consumers that decode only the old fields keep working.

## Non-goals / evidence

- Superseded half, now delivered: the duplicate P2 ticket requires a bounded per-job artifact-id snapshot on the LIVE `GET /v1/jobs` entry. Implemented as `JobInfo.artifacts` (max 64). Liveness is unchanged: the snapshot disappears with `JobGuard::drop`; there is no replay or retention promise.
- Dropped-frame recovery still rests on the artifact store (`GET /v1/artifacts/{id}/bytes`) and recorded provenance; the snapshot only removes the manifest round trip while the job is live. Consumers that read only `artifact_id`/`sha256`/`size_bytes` are unaffected.
